# BreatheWise Server Orchestration Layer

The server orchestration layer coordinates deterministic calculations, multi-source external data gathering, content safety verification, and language model integration behind a strict, dependency-injected pipeline.

## Architectural Responsibilities

1. **Deterministic Calculation Core Isolation**
   - The engine core (`src/core/`) remains 100% pure (no I/O, no network, no clock reads, no environment variables).
   - The server pipeline supplies contextual inputs (clock timestamps, geocoded coordinates, atmospheric observations) to the core evaluators.

2. **Dual-Path Advice Generation**
   - **Fast Path (`buildAdvice`)**: Asynchronous orchestration path that fetches cached atmospheric observations and weather in parallel, then executes pure, deterministic compute (`computeAdviceData`, <10ms). Returns complete recommendations with built-in, pre-verified i18n keys and parametric templates without invoking an LLM.
   - **Explain Path (`explainAdvice`)**: Enriches the computed advice with natural language narrative generated by Google Gemma 4 31B IT (via Jarvis Labs) through an ordered multi-stage security pipeline:
     1. Zod response schema validation.
     2. Quantitative number-whitelist guard (`findDisallowedNumbers`) with 1 regeneration retry citing only disallowed tokens.
     3. Clinical safety and guaranteed-prevention filter (`checkSafety`).
     4. Built-in explanation fallback (`source: "builtin"`) upon any guard violation.

3. **Follow-Up Assistant Pipeline (`answerQuestion`)**
   - Users may ask conversational questions regarding daily smog mitigation.
   - Grounding context is recomputed strictly server-side (client-supplied values are never trusted).
   - User queries and prior turns are strictly quarantined within `<user_question>` and `<prior_conversation>` delimiters.
   - Follows the identical guard order: (1) Output structure validation, (2) Number whitelist check with 1 retry, (3) Safety content filter.
   - Declines off-topic or clinical medical inquiries with `{ declined: true, reasonKey: "..." }`.

4. **HTTP API Middleware Layer (`src/server/http/`)**
   - Every API route is wrapped with `withApi`, enforcing:
     - Streaming body reading with hard 8 KB limit (HTTP 413).
     - Method allowlists (HTTP 405 + `Allow`).
     - Same-origin and cross-site protection (HTTP 403, no wildcard CORS).
     - Strict Zod validation without echoing submitted values (HTTP 400).
     - In-memory sliding-window rate limiter using salted SHA-256 IP hashing (HTTP 429 + `Retry-After`).
     - Structured log hygiene omitting bodies, profiles, coordinates, questions, or raw IPs.

5. **Composition Root (`src/server/container.ts`)**
   - Lazily instantiates real external adapters configured from environment variables.
   - Provides `setContainerForTests` and `resetContainer` for isolated testing.
