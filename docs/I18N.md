# BreatheWise Internationalization (I18N) Architecture & Hindi Localization

## Overview

BreatheWise is designed for families and communities across Indian urban centers confronting severe winter smog inversions. The interface and advice engine provide first-class support for **Hindi (हिन्दी)** alongside **English**, acknowledging that life-critical exposure guidance must be accessible in the user's primary language.

---

## 1. Localization Status & Review Protocol

- **Translation Status:** Comprehensive localization of all UI strings, AQI categories, recommended actions, parametric assumptions, safety disclaimers, built-in guidance, and calendar events.
- **Review Recommendation:** Initial translations have been reviewed for grammatical correctness and natural conversational phrasing in Devanagari script. A periodic native-speaker audit by bilingual public health and environmental science educators is recommended to maintain terminology alignment with CPCB (Central Pollution Control Board) public notices.
- **Digit Preservation Rule:** Numbers are rendered using the Latin numbering system (`hi-IN-u-nu-latn`, e.g., "15 µg/m³", "24 घंटे", "45 m³") via standard `Intl.NumberFormat` and `Intl.DateTimeFormat`. This maintains 100% numerical consistency with sensor feeds, the API schema, and the server-side number whitelist.

## 3. Parity & Validation Guarantees

Automated CI tests (`tests/unit/i18n-parity.test.ts`) enforce the following invariants:

1. **1:1 Key Parity:** Every leaf key defined in `src/i18n/en.json` must exist in `src/i18n/hi.json` with zero missing keys and zero untranslated empty strings.
2. **Placeholder Parity:** Every parameterized placeholder token (e.g. `{place}`, `{category}`, `{multiple}`, `{hour}`, `{pm25}`) must match exactly in both language catalogs.
3. **Script Verification:** Critical public health keys are asserted to contain Devanagari script characters (`[\u0900-\u097F]`).
4. **Pseudo-Localization (+40% Expansion):** Tested against a 40% length expansion to verify that mobile viewports (down to 320px width) do not produce unreadable text overflows or broken button wrappers.
